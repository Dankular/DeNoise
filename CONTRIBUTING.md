# Contributing

## Ground rules

- **Don't claim something works unless you ran it.** This project's docs
  distinguish "built and tested" from "unverified skeleton" throughout
  (see the table in [README.md](README.md)) -- that distinction is load-
  bearing, not decoration. If you touch `platform/macos` or the
  `platform/windows` COM shim without access to the relevant SDK/toolchain,
  say so in the PR rather than upgrading its status.
- **Ground platform-API code in a real header or a real, runnable
  reference**, not recollection. E.g. the PipeWire filter was written
  against `pipewire/filter.h` actually installed on the build machine,
  cross-checked against PipeWire's own `audio-dsp-filter.c` example; the
  macOS skeleton was written against a real fetched
  `AudioServerPlugIn.h`. If you can't get the real header, say so and mark
  the code as a sketch, the way `platform/windows/DeNoiseApo.h` does.
- **Never call ONNX Runtime (or anything else that allocates/blocks) from
  a realtime audio callback.** See "Realtime safety" in
  [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) -- every platform backend
  hands buffers across via `denoise::RingBuffer` to a worker thread
  instead. New platform backends should follow the same shape.
- **A stage's model contract is load-bearing, not a suggestion.** See
  [docs/MODELS.md](docs/MODELS.md). If you need a new `StageKind` or a
  different tensor shape, update that doc in the same change.

## What to work on

[docs/ROADMAP.md](docs/ROADMAP.md) is the current, prioritized task list
-- everything on it traces back to [docs/KRISP_RESEARCH.md](docs/KRISP_RESEARCH.md)
(primary-sourced research on what Krisp actually ships) or a known hole in
this repo's own state. Pick an unchecked item, or open an issue if you're
looking at a gap that isn't listed yet.

## Building and testing

See the Quick start in [README.md](README.md). In short:

```sh
cmake -B build -DONNXRUNTIME_ROOT=/path/to/onnxruntime-linux-x64
cmake --build build -j"$(nproc)"
ctest --test-dir build --output-on-failure
```

All tests must pass. If you add a pipeline stage, model contract change,
or platform-backend behavior, add a test that would fail without your
change -- see `tests/` for the existing pattern (deterministic ONNX
fixtures generated by `scripts/gen_test_models.py`, exact expected outputs
checked in C++).

## Adding/changing the test ONNX fixtures

Edit `scripts/gen_test_models.py`, regenerate (`python3
scripts/gen_test_models.py`), and commit the resulting files under
`models/test/`. CI regenerates them itself and fails if the committed
files don't match byte-for-byte -- don't hand-edit `models/test/*.onnx`.

## Platform backends

Read the target platform's README (`platform/linux/README.md`,
`platform/macos/README.md`, `platform/windows/README.md`) first -- each
one lists exactly what's implemented, what's stubbed, and what's
unverified for that backend. Keep those lists current as you change the
code; they're the main way this project stays honest about its own state.
